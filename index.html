How to use this page
  1. Search. Type a data structure, algorithm, Java method or loop shape in the box. Pick a result to see its Big O for every operation and why. Press / to jump to the box.
  2. Ladder. The seven rungs run fastest to slowest. Click one to filter the catalog to that class; click again to clear.
  3. Chart. Drag the n slider, switch log/linear, and hover to read every class at one n. Turn O(2ⁿ) and O(n!) on in the legend to see why brute force dies.
  4. Catalog. Four tabs: data structures, algorithms, Java calls, code patterns. A * means amortized or average case; the worst case is in the notes.
  5. Code patterns. The cards at the bottom are the loop and recursion shapes from class. Match the shape, name the class.

The shapes the professor used in the Week 5 lab.
Big O is the asymptotic upper bound: the worst case as n grows without limit. Constants and lower-order terms are dropped, so 50 n is O(n) and 5 days is O(1). Ω is the lower bound, Θ is tight. Hash map figures assume a good hash function; the worst case for a hash map is O(n) when everything collides.
